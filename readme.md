1. 서비스 컨셉: "스마트 디지털 포워더 (짐고형 견적 산출기)"
사용자가 화물 규격과 조건을 넣으면, 수집된 항로별 데이터와 환율을 기반으로 출발지부터 목적지까지 예상되는 해상/항공 물류비 견적서를 뽑아주고, 항로별·인코텀즈 조건별 비교 분석을 제공하는 대시보드입니다. <목적 : 기본 견적서만 딱 뽑아준다.>

2. 가이드라인 평가표 1:1 완벽 충족 설계
① 데이터 수집 및 연동
필수 항목 충족 (HS CODE, 국가, 반복문 다량 수집, 보안):
수집 데이터(=기준 데이터)
관세청/해양진흥공사/공공데이터포털의 "주요 국가/항로별 해상 컨테이너/LCL 운임 통계 데이터"
품목별 수출입 관세율 및 기준 데이터 (HS CODE 및 대상 국가 매핑)
구현: 여러 출발-도착 국가/항구 및 주요 HS CODE 카테고리를 리스트로 두고 반복문(for)을 돌려 API/웹에서 기초 단가 및 기준 데이터를 수집하여 로컬 DB/데이터프레임으로 적재합니다.
보안: API 키는 .env로 격리하고 .gitignore에 등록.

② 데이터 전처리
환율 API를 활용한 KRW 원화 변환 및 단위 통일:
해상/항공 운임(USD 기준), 해외 현지 비용(USD/EUR) 등을 한국수출입은행/공공 환율 API를 호출해 실시간 KRW로 변환
정제 및 구조화:
CBM(부피)과 Weight(중량)에 따른 운임 톤(R/T, Revenue Ton) 산출 파생 컬럼 생성 (max(CBM, Weight/1000)).
결측치(특정 항로 부대비용 누락 등) 처리, 수치형 변환, 규격 단위(톤, kg, TEU, CBM) 표준화.

③ 지표 및 분석 설계

KPI 1:   관세사 이용 비용 절감
KPI 2 :  open ai를 활용하여 사용자가 현재 보유하고 있는 예산에 맞는 금액으로 조정

분석 타당성 & 시장 시사점 (2문장 이상):
하단 인사이트 콜아웃: "선택하신 [부산-LA] 항로는 성수기 할증료(PSS) 반영으로 전분기 대비 운임이 약 8.5% 높은 상태입니다. 현재 물동량과 인코텀즈 조건(FOB vs CIF)을 고려했을 때, 해상보험을 직접 부보하는 CIF 조건보다 바이어가 해상운임을 부담하는 FOB 조건이 현시점 화주 리스크를 12% 낮출 수 있습니다."

④ 대시보드 화면 및 인터랙션
UI 활용 능력 (인터랙션 10점):
Streamlit의 다양한 위젯을 적극 활용:
st.selectbox / st.radio: 출발항(부산/인천), 목적국(미국/베트남/독일), 인코텀즈(FOB, CIF, DDP 등), 운송 모드(FCL 컨테이너 vs LCL 소량)
st.number_input / st.slider: 가로·세로·높이(부피) 및 무게, 화물 신고 가격
st.checkbox: 적하보험(Marine Insurance) 가입 여부

화면 구성 & 시각화:
상단: 핵심 견적 요약 카드 3종 (st.metric)
중단 좌측: 견적서 명세서 테이블 (내륙운임 / 해상운임 / 터미널비용 / 보험료 / 관세 등 항목별 상세 표)
중단 우측: 비용 구성비 도넛 차트 (물류비 중 해상운임 vs 부대비용 vs 보험료 비중 시각화)
하단: 항로별/월별 운임 추이 시계열 차트 (선택한 항로의 최근 추세를 보여주어 기간 비교성 충족)

3. 결론
더 이상 "무역수지나 국가 전체 수출입액 통계를 억지로 끼워 넣을 필요"가 전혀 없어졌습니다.

프론트엔드: 트레드링스 짐고처럼 깔끔하고 인터랙티브한 견적 산출 폼 구축.
백엔드/데이터: 반복문 기반 항로·품목 기준 데이터 수집 + 실시간 환율 변환 + CBM/보험료 연산 로직.
분석/출력: 상세 견적 명세서 + 물류비 구성 비율 차트 + 최근 운임 추이 비교 및 운송 시사점 브리핑.
